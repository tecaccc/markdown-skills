Beautify the existing .pen presentation file specified in: $ARGUMENTS

If no .pen file is specified, list `*.pen` files in the current directory and ask the user to pick one.

This skill is the **polishing stage** that runs **after** `ppt-editor`. It does **not** change content — it improves the *visual* quality of slides that already exist.

## Constraints

- **Must use the `pencil` MCP tool** for every read and write on the .pen file. Never call `Read` / `Edit` / `Write` on `.pen` files — they are encrypted.
- **Do not change semantic content.** No new bullets, no rewritten copy, no removed facts. Only visual adjustments: position, size, color, font weight, decorative shapes, alignment, spacing, hierarchy emphasis.
- **Preserve the AnHeng brand palette and typography** as defined in [../ppt-editor/specs/style-guide.md](../ppt-editor/specs/style-guide.md). Beautification works within the brand, not against it.
- **Idempotent**: re-running on an already-polished deck should be a no-op (the audit should find few issues). Track what was already adjusted via a slight tolerance on the checklist.
- **One change set per session** — apply, screenshot, report. Do not loop indefinitely.

## Workflow

### Phase 1 — Open & Inventory

1. Call `mcp__pencil__open_document` with the .pen file path.
2. Call `mcp__pencil__get_editor_state` to confirm the document is loaded and get the page list.
3. Call `mcp__pencil__snapshot_layout` to get the full layout tree (positions, sizes, types of every node on every page).
4. Read [../ppt-editor/specs/style-guide.md](../ppt-editor/specs/style-guide.md) and [../ppt-editor/specs/diagram-patterns.md](../ppt-editor/specs/diagram-patterns.md) for the brand reference.

**Output of Phase 1**: an internal page roster — for each page, its type (cover / toc / chapter / content / contact), the diagram layout if any (inferred from shape arrangement), and a list of all visual elements.

### Phase 2 — Per-Page Aesthetic Audit

For each page in order:

1. Call `mcp__pencil__get_screenshot` for the page to see what it actually looks like.
2. Score the page against the **Aesthetic Checklist** below. Each item is pass / warn / fail.
3. Build a per-page issue list — what's wrong, what to fix, what specific transformation to apply.

#### Aesthetic Checklist

| # | Check | Pass criterion | Common failure | Fix |
|---|-------|----------------|----------------|-----|
| 1 | **Visual hierarchy** | Exactly one element is the unmistakable "hero" (largest font OR most saturated color OR isolated by whitespace) | Three elements compete for attention | Enlarge the hero (target ratio ≥ 2× next-largest); demote others |
| 2 | **Whitespace / breathing room** | ≥ 20% of slide area is empty (background only) | Edges touch content; <10% empty | Increase margins to 60px+; shrink overly large elements |
| 3 | **Alignment grid** | All major elements snap to a shared left edge OR a shared center axis | Random x positions, ±5–20px drift | Snap each element to nearest grid line (multiples of 8 or 12) |
| 4 | **Typography rhythm** | No more than 3 distinct font sizes per page; sizes follow the hierarchy in style-guide | 5+ sizes, or H1 and body too close in size | Collapse near-duplicate sizes; widen the ratio between hierarchy levels |
| 5 | **Color discipline** | Brand-red used only for accent (≤ 15% of colored area); body text stays brand-blue | Red walls, rainbow palette, off-brand grays | Recolor errant elements; keep red for hero / accent / divider only |
| 6 | **Decorative accents present** | At least one of: divider line under title, vertical accent bar, callout card, large number, corner accent | Title floats with no anchor; page feels naked | Add a 68×5 `#C00000` divider under the title; or a 6×440 `#08287F` left bar |
| 7 | **Bullet density** | If bullets present: ≤ 5 bullets, each ≤ 20 Chinese chars | Wall of 8+ bullets, long sentences | Flag for **content review** — beautifier won't rewrite, but will tighten spacing and add a hero highlight extracted from the longest bullet |
| 8 | **Diagram quality** | Diagram nodes evenly spaced; arrows aligned; labels fit inside containers | Overlapping nodes, labels truncated, asymmetric gaps | Recompute positions per diagram-patterns.md; re-flow labels |
| 9 | **Cross-page consistency** | Same page-type (e.g. all content pages) share title position, font, color | Title at y=120 on page 4 but y=140 on page 6 | Normalize to spec values |
| 10 | **Visual rhythm** | No 3 consecutive content slides with the same layout AND same density | Five identical-looking pages in a row | Cannot fix structurally; flag in report so user can re-plan |
| 11 | **Edge safety** | No element within 20px of canvas edge (unless intentional full-bleed background) | Text bleeding past edge, image overflowing | Reposition / resize within safe zone |
| 12 | **Contrast** | Text on dark backgrounds is `#FFFFFF` or near-white; text on light backgrounds is brand-blue or darker | Light-gray text on white, blue text on dark blue | Swap color to ensure ≥ 4.5:1 contrast ratio |

### Phase 3 — Beautification Plan

Aggregate all per-page issues into a single ranked plan. For each issue, record:

- Page number
- Check # and short description
- Concrete transformation (e.g., "move element id=abc from y=145 to y=120; change font size 18 → 16")
- Risk level: `safe` (pure visual, no content impact) / `careful` (might affect text fit) / `flag-only` (cannot fix automatically — report to user)

Print this plan to the conversation **before applying anything**. Group by page.

If the user invoked with `--apply auto`, proceed directly to Phase 4. Otherwise (`--apply review` or no flag), ask: *"Apply these N changes? [yes / select / no]"*. On `select`, let the user pick which page groups to apply.

### Phase 4 — Apply Fixes

Apply the approved changes using `pencil` MCP tools:

- For position / size / color / font changes on specific nodes: use `mcp__pencil__batch_design` (single batched edit per page is preferred over many small calls).
- For project-wide property normalization (e.g., "all titles to font size 32, color #08287F"): use `mcp__pencil__replace_all_matching_properties`.
- For adding missing decorative shapes (divider lines, vertical bars, callout cards, corner accents): use `mcp__pencil__batch_design` with a `create` operation.
- For finding free space when adding a new element: use `mcp__pencil__find_empty_space_on_canvas`.

After all fixes for a page are applied, take a fresh screenshot via `mcp__pencil__get_screenshot` and re-run **only the failed checks** from Phase 2 on that page. If a fix did not stick, log it but do not retry more than once.

### Phase 5 — Validation & Report

Produce a final report to the user:

1. **Pages reviewed**: total count.
2. **Issues found**: total, broken down by check # (e.g., "Hierarchy: 3, Whitespace: 5, Alignment: 8 ...").
3. **Fixes applied**: per page, list of transformations.
4. **Flagged (not auto-fixable)**: items requiring user action — content rewrites, structural re-planning, deck-level rhythm problems. For each, suggest the next concrete step (e.g., "Re-run `/ppt-planner` to convert Slide 7 into a flow diagram").
5. **Before/after screenshots**: include 2–3 representative pages.

## Specific Transformation Patterns

These are reusable transformations the beautifier knows how to apply. Use them as building blocks.

### T1 — Add divider under title
Insert a `68×5` rect, fill `#C00000`, at `x=46, y=205` (Page 4 standard). Append to page after title node.

### T2 — Add vertical accent bar
Insert a `6×440` rect, fill `#08287F`, at `x=30, y=220`. Use when a content page has no left-edge anchor.

### T3 — Promote hero element
Identify the most important text on the page (often the slide's first non-title element, or one matching the `key_highlight` from a sibling `.ppt-design.md` if present). Increase its font size by 1.5–2× and apply bold. Demote competing elements by reducing their size by 25%.

### T4 — Convert oversized bullet list to icon-grid
If a content page has 3–6 short bullets, propose (do not auto-execute) restructuring them as a 3×N icon grid per [diagram-patterns.md](../ppt-editor/specs/diagram-patterns.md#icon-grid---parallel-features). Mark as `careful` — requires user confirmation because it changes visual structure significantly.

### T5 — Normalize spacing
For any group of N elements stacked vertically, recompute y positions so vertical gaps are equal (median gap of the existing layout, rounded to nearest 8).

### T6 — Snap to grid
Round every element's x and y to the nearest multiple of 8 (or 12 if 8 produces visible misalignment). Skip elements that are intentionally off-grid (full-bleed backgrounds).

### T7 — Add callout card around key highlight
Wrap the hero text in a rounded rect (corner radius 8, fill `#F5F5F5`, 1px border `#CCCCCC`, padding 16px). Use when the page is otherwise too empty.

### T8 — Fix color drift
For each text node:
- If on a dark background (fill ≤ 30% brightness) and text color is not white-ish → set to `#FFFFFF`.
- If on a light background and text is not in the brand palette → set to `#08287F`.

### T9 — Recompose diagram
For pages identified as diagram layouts (by sibling `.ppt-design.md` or by structural inference), recompute every node position per [diagram-patterns.md](../ppt-editor/specs/diagram-patterns.md) using the page's content area `x=46, y=220, w=1188, h=440`. This is heavy — only run when the audit shows ≥ 3 alignment/spacing failures on the same diagram page.

### T10 — Add corner accent
Insert a `24×24` right-triangle shape (or square if triangles aren't supported), fill `#C70019`, at the top-right corner of the content area. Used sparingly — only for `mood: confident` chapters (read from sibling `.ppt-design.md` if available).

## Edge Cases

- **`.pen` file not found / pencil cannot open**: report the error and stop; do not fall back to text-based reading.
- **Sibling `.ppt-design.md` exists**: read it via the `Read` tool to recover `key_highlight`, `layout`, `density`, `accent_elements`, `mood` for each slide. This significantly improves audit quality — without it, the beautifier must infer everything from the visual layout.
- **No issues found**: report "Deck already meets the aesthetic checklist — no changes needed." Do not invent issues to fix.
- **User says "skip page X"**: honor it; remove all changes for that page from the plan.
- **A fix would push content past the canvas edge**: revert the fix, mark the issue as `flag-only`, and add it to the user-action list.
- **The page is empty or has only background**: skip it; nothing to beautify.

## Output

The skill produces:

1. **In-place visual changes** to the .pen file (via pencil MCP).
2. **A report** to the conversation, as described in Phase 5.
3. **No new files** unless the user explicitly asks for a backup copy (in which case suggest they do it via their OS / version control before invoking the skill).
